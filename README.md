# Wireward

Журнал усіх SQL-запитів, які студенти виконують під час лабораторних з баз
даних — включно з тими, що впали на синтаксисі, — і візуалізація їхньої
реальної роботи в часі.

Записує не сервер, а **власний проксі протоколу PostgreSQL**: він стоїть у
розриві між клієнтом студента (psql, DBeaver, DataGrip) і кластером, тому
бачить навіть те, що до виконання так і не дійшло.

## Що вміє

- **Журнал кожного запиту** — текст, нормалізований відбиток, вид, тривалість,
  кількість рядків, `SQLSTATE` і позиція помилки, клієнт і версія. Простий і
  розширений протоколи, `COPY`, курсори, скасування.
- **Екран «Активність»** — теплокарта день × година, стрічка сесій із
  засічками помилок, крива помилок, автоматичні точки застрягання.
- **Підсвічування помилок, яких СУБД не помічає** — `= NULL`, `NULL` у списку
  `NOT IN`, `HAVING` без `GROUP BY`, зʼєднання без умови тощо.
- **Прив'язка запитів до лабораторних** за змістом (нечітка схожість форми
  запиту), а не за часом виконання.
- **Персональна база кожному студенту** — своя роль, свій слот tablespace,
  м'яка квота.
- **Тверді ліміти на боці проксі** (`work_mem`, `statement_timeout`) — навіть
  якщо студент знімає їх сесійним `SET`.
- **Резервне копіювання** — логічна копія журналу (`make backup`) і фізична
  копія кластера в S3-сумісне сховище через wal-g.

## Склад

| Каталог | Що це | Мова |
| --- | --- | --- |
| `pgproxy/` | проксі протоколу PostgreSQL, журналювання, квоти | Go |
| `front/` | кабінет студента, адмінка, екран «Активність», OIDC | Python (FastAPI) |
| `postgres/` | образ кластера, ролі, схема, провізіонінг | SQL + bash |
| `scripts/` | розгортання, бекап/відновлення, перевірки | bash + Python |

## Швидкий старт

Готові образи є на Docker Hub (`potapuff/wireward-postgres`,
`potapuff/wireward-pgproxy`, `potapuff/wireward-front`) — `compose.yaml`
збирає їх з вихідного коду цього репозиторію локально, тож `docker pull`
окремо не потрібен.

```bash
git clone <URL цього репозиторію>
cd wireward
cp .env.example .env      # за потреби підправити OIDC/порти
make up                   # згенерує секрети, збере образи, підніме стек
make check                # критерії готовності
make psql                 # psql суперкористувачем у базу observer
```

Веб-кабінет доступний на `http://127.0.0.1:8001`. Поки зовнішній OIDC
(LMS) не налаштований, вхід можна перевірити в обхід нього — **лише
локально**:

```bash
DEV_LOGIN_ENABLED=1 SESSION_COOKIE_SECURE=0 docker compose up -d front
```

Публічний вихід назовні (домен, TLS-сертифікат через Caddy) — профіль
`server`:

```bash
docker compose --profile server up -d
```

Змінні `WEB_HOST` і `ACME_EMAIL` — у `.env`.

### Корисні команди

| | |
|---|---|
| `make up` / `down` / `reset` | підняти, зупинити, знищити томи й підняти з нуля |
| `make check` | критерії готовності стенду (схема, права, партиції) |
| `make health` | стан: журнал, партиції, квоти, бекап, служби |
| `make backup` / `restore-test` | копія журналу і доказ, що вона відновлюється |
| `make test-provisioning` | цикл провізіонінгу студента та ізоляція |
| `make test-clients` | матриця сумісності: psql, psycopg3, pgjdbc |
